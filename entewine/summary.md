  根本原因：小消息对跳数更敏感

  两种 mapping 下的通信路径对比：
  ┌────────────────────────────┬──────────────┬──────────────────────┬───────────────────────┐
  │          通信类型          │   消息大小   │    Baseline 跳数     │       OPT 跳数        │
  ├────────────────────────────┼──────────────┼──────────────────────┼───────────────────────┤
  │ TP All-Reduce (tag 50)     │ 221 KB (小)  │ 1-2 跳 (TP 紧凑 2×2) │ 3-4 跳 (TP 分散)      │
  ├────────────────────────────┼──────────────┼──────────────────────┼───────────────────────┤
  │ FTD All-to-All (tag 70/80) │ 1.77 MB (大) │ 3-4 跳 (FTD 分散)    │ 1-2 跳 (FTD 紧凑 2×2) │
  └────────────────────────────┴──────────────┴──────────────────────┴───────────────────────┘
  关键的物理直觉：

  1. TP 消息小 (221KB)，是延迟敏感型：传输时间短，所以每一跳的延迟和 ACK 往返时间在总传输时间中占比很大。OPT 把 TP 跳数从 1-2
  跳增加到 3-4 跳，ACK 往返开销显著增加。
  2. FTD A2A 消息大 (1.77MB)，是带宽受限型：传输时间长（被带宽主导），跳数增减对总传输时间的影响很小。OPT 把 A2A 跳数从 3-4
  跳减少到 1-2 跳，节省的绝对时间有限。
  3. TP All-Reduce 是串行链式广播（core0→1→2→3，每步要等 ACK），跳数增加的延迟会被4 步串行放大。而 FTD A2A 只有 3 个
  peer，且可以并行发送。

  总结

  OPT mapping 的设计思路是"让 FTD 紧凑、牺牲 TP 距离"，但实际上：
  - TP 通信虽然数据量小，但对跳数极其敏感（串行 + ACK 往返）
  - FTD A2A 虽然数据量大，但对跳数不敏感（带宽主导）

  所以 OPT 在 TP 上损失的延迟 > 在 FTD A2A 上节省的延迟，导致整体反而变慢了约 1,150 us (+0.07%)。

  理想的 mapping 应该同时让 TP 和 FTD 都尽量紧凑，但在 4×4 mesh 上这两者是矛盾的（TP 组和 FTD 组正交），无法同时优化。

  结论

  OPT mapping 把 TP All-Reduce 的 ACK 延迟增加了 +30,382 cycles，而 FTD A2A 几乎没有受益。所以整体通信慢了
  2.1%，导致端到端延迟略高。核心问题是：大消息（A2A 1.77MB）对路径长度不敏感，小消息（TP 221KB）对路径长度很敏感。
